制定日期：2026-09-06。此文件是下一阶段计划，不是已完成的全国岗位调查。用户目标是扩展可探索职业范围至 75–85%；不是声称当前已经覆盖该比例。现有 Pack 深度保留，下一阶段优先补广度。

## 首轮范围与批量目标（建议工作参数）

- 以中国大陆为主，分别记录应届/早期职业和有经验岗位；专业不限于临床医学，逐条保留 JD 对医学、药学、公卫、护理、检验等专业的原始要求。不能把“相关专业”自行翻译为全部医学背景。
- 两条支线分别统计：医疗相关就业方向、医疗行业之外的通用/跨行业方向。后一条同样允许进入候选池，不因“医学优势不明显”排除，也不直接判定适合。升学申请单列，不计就业角色数。
- 首轮建议采集 100–150 份去重 JD/官方岗位说明，形成约 30–50 个候选角色范围。这是工作量目标，不是保证能发现相应数量或达到全国 85% 覆盖；不为凑数拆别名。
- 优先近期 12 个月来源，同时保留明确标记的历史参考；按职能、机构、地区和责任层级分层，记录每层已检索/未检索情况。不得只搜索“医学转行”或现有 Pack 名称。
- 稀有方向允许先保留单一来源；常见角色尽量寻找两个不同雇主的独立 JD。不同平台转发同一岗位不算独立来源，两个 JD 也不等于完成 Canonical 验证。

## 收集 → 去重 → 分类 → 收录

1. **建立搜索网格。** 使用现有职能族并标记未覆盖类别；组合机构招聘栏目、任务词和专业要求词检索。首轮扫描后允许新增待审职能，不把现有 11 类当成不可扩展全集。
2. **保存来源。** 每条保留 URL、雇主、原岗位名称、发布日期（未知则 null）、采集日期、地点、经验层级、保留摘录、内容摘要、来源状态和重复来源关联。不收集候选人资料或无关个人联系方式。
3. **提取最低限度信息。** 主要任务、典型交付物、学历/专业/资格原文、机构类型、业务领域、可选产品阶段；缺失信息标为未知，禁止补造。
4. **先按职责分组，再处理名称。** 同名异岗可拆为待审范围；异名同岗可候选归并。判断看任务/交付物/责任对象，而非只有标题相似度。算法/LLM 可提出分类建议，不能自动确认岗位等价或医学可迁移性。
5. **审核关联。** 记录 equivalent / narrower / adjacent / unresolved，保留对应摘录和审核理由。高级、负责人、支持等责任差异必须可见，不能合并后丢失要求。标准职业编码可暂空，不强配。
6. **浅层收录。** 候选角色不要求完整 Pack、Card 或匹配规则。先明确“来源观察到、范围待审”等状态，展示什么、不能推断什么；不存在来源的词条只保留为待检索线索。
7. **再挑深做对象。** 首轮广度报告完成后，根据来源质量、用户需求和可复用资产选择少数方向深化，不在采集中逐个做完 Pack 才继续下一个。

建议先交付可审阅的 JSON/CSV 候选登记表与 Markdown 汇总，不立即写进 Canonical 或当前 SQL。注册表最小字段：candidate_id、raw_titles、proposed_label、object_type、function_family_proposal、organization_type、business_domain、lifecycle_context、task_excerpts、deliverable_excerpts、entry_requirement_excerpts、jd_source_ids、source_status、existing_catalog_relation、scope_review_status、review_note。具体文件/schema 在采集阶段确认，本计划不创建空的第二套职业真值。

## 进度怎么计算

- 先报告搜索层覆盖、独立雇主数、去重 JD 数、候选角色数、已核对范围数及无来源线索数。
- 建立有版本的参考候选集合后，可报告“参考集合中已收录并核对的角色比例”，以 75–85% 为阶段目标。冻结分母版本并保留未归类项，新增方向后更新集合版本，不能仅删掉难归类项提高比例。
- 另用独立留出/后续来源样本观察尚未收录的角色，防止用建库时的样本自证完整。报告这个样本覆盖率时，明确它不是全国市场份额或用户匹配百分比。
- Pack 覆盖、Card 深度、解释规则覆盖另列；浅层目录扩张不改变当前两个解释方向，也不授权扩大 runtime target。

首轮完成条件是得到一个显著扩大的、去重可追溯的候选目录和遗漏清单，而不是完成每个角色的深度职业包。现有 Pack 的深度维护只处理事实与边界错误，不抢占本轮广度优先级。
